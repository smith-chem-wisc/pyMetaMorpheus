# Results — finding and reading your output

Every verb returns a `RunResult`. A run's output directory contains one subfolder per task, named
`Task<N><TaskType>` (e.g. `Task1SearchTask`), and `RunResult` gives you typed access to each.

```python
result = mm.search("myrun.mzML", "proteins.fasta", "out")

result.output_dir          # Path("out")
result.tasks               # [TaskResult(index=1, task_type="SearchTask", ...)]
result.search              # the SearchTask TaskResult (or None)
result.calibration         # CalibrationTask TaskResult (or None)
result.gptmd               # GptmdTask TaskResult (or None)
result.glyco_search        # GlycoSearchTask TaskResult (or None)
result.task("XLSearchTask")  # look up any task type by name
```

## Start here: the run summary

After any run, the fastest way to see what happened is MetaMorpheus's own human-readable summary —
it lists ID counts, FDR, and the settings used. No parsing required:

```python
print(result.search.summary.read_text(encoding="utf-8"))   # results.txt
```

There's also a ready-to-cite methods paragraph:

```python
print(result.search.prose.read_text(encoding="utf-8"))     # AutoGeneratedManuscriptProse.txt
```

## Which file answers which question

Each `TaskResult` exposes the standard output files as path accessors (each returns `None` if that
file isn't present, so you can safely check across task types):

| I want to know… | accessor | file |
|---|---|---|
| a summary of the whole run | `summary` | `results.txt` |
| every peptide-spectrum match | `all_psms` | `AllPSMs.psmtsv` |
| identified peptides (FDR-controlled) | `all_peptides` | `AllPeptides.psmtsv` |
| protein groups + their abundances | `all_proteins` / `quantified_proteins` | `AllQuantifiedProteinGroups.tsv` |
| peptide-level quantities | `quantified_peptides` | `AllQuantifiedPeptides.tsv` |
| individual quantified peaks | `quantified_peaks` | `AllQuantifiedPeaks.tsv` |
| a spectral library (if you asked for one) | `spectral_library` | `*.msp` |
| a methods paragraph | `prose` | `AutoGeneratedManuscriptProse.txt` |
| the standard mzIdentML file | `mzid` | `*.mzID` |
| calibrated spectra (Calibration task) | `calibrated_spectra` | `*-calib.mzML` |
| a PTM-augmented database (GPTMD task) | `gptmd_database` | `*GPTMD.xml` |

For anything else in the folder: `result.search.file("SomeName.tsv")` or `.glob("*.tsv")`, and
`result.search.directory` is the folder itself.

## Reading a results table

The `.psmtsv` / `.tsv` files are plain **tab-separated tables** — open them in Excel, or read them in
Python. Pick whichever fits; the first needs nothing but the standard library.

=== "Standard library (zero deps)"

    ```python
    import csv

    with open(result.search.all_peptides, encoding="utf-8", newline="") as fh:
        rows = list(csv.DictReader(fh, delimiter="\t"))

    print(len(rows), "peptide rows")
    print(rows[0].keys())              # every column name
    print(rows[0]["Base Sequence"])    # a single value
    ```

=== "pandas (nicer)"

    ```python
    import pandas as pd

    df = pd.read_csv(result.search.all_peptides, sep="\t")
    print(df.shape)
    df.head()

    # e.g. confident peptide IDs at 1% FDR:
    confident = df[df["QValue"] <= 0.01]
    print(len(confident), "peptides at q ≤ 0.01")
    ```

    `pandas` is optional: `pip install "pymetamorpheus[pandas]"`.

=== "pyMzLib (typed objects)"

    ```python
    import pymzlib
    psms = pymzlib.readers.read_results(str(result.search.all_psms))
    ```

    The outputs are standard mzLib result files, so pyMzLib parses them natively. Install with
    `pip install "pymetamorpheus[pymzlib]"` (see the note below).

!!! tip "Counting identifications"
    For "how many did I identify?", the usual figure is **target peptides at q ≤ 0.01** from
    `AllPeptides.psmtsv` (not raw PSM rows). The pandas snippet above shows exactly that.

## Why paths, not parsed tables?

pyMetaMorpheus returns **paths**. The outputs are standard mzLib result files, and re-parsing them
here would duplicate work and drift from the format MetaMorpheus owns. You choose how to read them —
the standard library for a quick look, pandas for analysis, or pyMzLib for typed objects.

!!! note "pyMzLib isn't on PyPI yet"
    The `[pymzlib]` extra installs pyMzLib from source over git. Do **not** `pip install pymzlib` on
    its own — an unrelated package of the same name exists on PyPI. This resolves once pyMzLib is
    published (gap G-dist). `csv` and `pandas` need none of this and work today.
